# Руководство по запуску, настройке AI и передаче проекта

## Что создано

Omega Illustrator — локально запускаемый веб-редактор, который собирает композиции из предоставленных векторных SVG, позволяет менять объекты и экспортировать результат в SVG. В составе есть приложение на .NET 10, отдельная библиотека `Omega.AI.Gateway`, API-адаптеры, каталог оригинальных SVG, три примера и инструмент извлечения ресурсов из Figma.

AI предлагает только проверяемый JSON-план. Приложение проверяет ID предметов и само строит SVG из каталога; при ошибке провайдера доступен локальный смысловой подбор. Произвольный SVG, HTML или скрипт от модели в сцену не вставляется.

## Самый простой запуск без Visual Studio

1. Скачайте `OmegaIllustrator-Delivery-2026-11-03.zip` и соседний `.zip.sha256`.
2. При желании проверьте целостность архива в PowerShell:

   ```powershell
   $zip = '.\OmegaIllustrator-Delivery-2026-11-03.zip'
   $expected = (Get-Content "$zip.sha256" -Raw).Trim().Split(' ')[0]
   $actual = (Get-FileHash $zip -Algorithm SHA256).Hash.ToLowerInvariant()
   if ($actual -ne $expected) { throw 'SHA-256 не совпал: архив повреждён или изменён.' }
   'SHA-256 совпал.'
   ```

3. Распакуйте ZIP в отдельную папку.
4. Запустите `Start-OmegaIllustrator.cmd`. Оставьте открывшееся консольное окно работающим.
5. Откройте в Edge или Chromium `http://127.0.0.1:5190`.
6. Чтобы остановить приложение, закройте консольное окно.

Это self-contained сборка Windows x64: установленная Visual Studio, включая Visual Studio 2026, и отдельная установка .NET для обычного запуска не нужны. Для другой архитектуры или ОС эта сборка не предназначена.

Если адрес не открывается, проверьте, что консольное окно не закрыто и порт `5190` не занят другой копией приложения. Не публикуйте этот локальный HTTP-сервер напрямую в интернет или локальную сеть: этот пакет подготовлен для проверки на одном компьютере.

## Подключение API-провайдера

1. Запустите приложение и откройте **Подключение ИИ** (`http://127.0.0.1:5190/ai`).
2. В форме **Подключения через API** создайте профиль: название, протокол, базовый URL и API-ключ.
3. Для OpenAI-совместимого протокола укажите имя заголовка `Authorization` и префикс `Bearer `, если провайдер использует стандартную Bearer-авторизацию.
4. Нажмите **Сохранить API-профиль**. Приложение сохранит профиль, проверит соединение и запросит каталог моделей.
5. Выберите активное подключение и нужную модель. Для повторной проверки нажмите **Проверить соединение и загрузить модели**.
6. Вернитесь в редактор, выберите режим **По смыслу**, задайте тему и нажмите кнопку подбора. Статус покажет, ответила ли модель или включились локальные правила.

### Примеры настроек

| Сервис | Протокол | Базовый URL | Заголовок ключа |
|---|---|---|---|
| OpenRouter | OpenAI-compatible | `https://openrouter.ai/api/v1` | `Authorization`, префикс `Bearer ` |
| OpenAI API | OpenAI-compatible | `https://api.openai.com/v1` | `Authorization`, префикс `Bearer ` |
| Anthropic | Anthropic Messages | `https://api.anthropic.com` | приложение автоматически использует `x-api-key` |
| Google Gemini API | Google Gemini | `https://generativelanguage.googleapis.com` | приложение автоматически использует `x-goog-api-key` |
| Локальный сервер модели | OpenAI-compatible | адрес локального сервера, обычно с `/v1` | параметры зависят от локального сервера |

Для OpenRouter введите ключ, созданный в своём аккаунте OpenRouter. Бесплатный тариф или модель с пометкой `:free` не гарантирует доступность: провайдер может ограничить частоту или квоту и вернуть HTTP 429. Используйте ID модели из списка, который приложение получило от выбранного API; каталог и доступность зависят от аккаунта провайдера.

Режим OpenAI-compatible подходит только сервисам, которые действительно поддерживают совместимые вызовы Chat Completions и нужный список моделей. Установка произвольного URL не превращает несовместимый API в поддерживаемый. Для других протоколов библиотеке требуется отдельный адаптер.

### Хранение ключей

Вводите ключ только на странице `/ai`. API-профили и зашифрованные учётные данные сохраняются в локальном хранилище пользователя `%LOCALAPPDATA%\OmegaIllustrator`; папка не включена в ZIP и исключена из Git. После сохранения поле ключа очищается. При редактировании профиля оставьте поле пустым, чтобы сохранить прежний ключ. На новом компьютере создайте профиль и введите ключ снова. Не отправляйте ключ в видео, скриншотах, логах или Git.

Для изолированного тестового запуска можно до запуска задать `OMEGA_DATA_DIR` на отдельную локальную папку. Не задавайте этот путь внутри каталога, который публикуется или синхронизируется с общим облачным хранилищем.

## ChatGPT OAuth: личная локальная демо-проверка

Страница `/ai` позволяет начать Sign in with ChatGPT через системный браузер. Вход и использование плана — разные согласия: запросы по плану должны быть явно разрешены в потоке OpenAI. Ключ не вводится и не передаётся приложению; запросы учитываются в доступном пользователю плане и его ограничениях. Успешный вход сам по себе не гарантирует право на inference, наличие нужной модели или свободную квоту. Если согласие или использование плана не предлагается, проверьте eligibility аккаунта либо используйте собственный API-профиль.

**Граница этой поставки:** ChatGPT OAuth включён для локальной проверки работодателем/разработчиком на собственном аккаунте. Не разворачивайте эту интеграцию как производственный тариф и не продавайте доступ к личному плану. Не объединяйте аккаунты, не передавайте чужие токены и не обходите лимиты. Для production используйте API выбранного провайдера с отдельным биллингом. OpenAI отдельно публикует программу Sign in with ChatGPT для локальных open-source приложений; для коммерческого или удалённо размещённого сервиса требуется сверить актуальные условия и получить доступ по соответствующей программе. Это демо-приложение не заявляет такого допуска. Смотрите [правила использования ChatGPT plan в приложениях](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites), [раздельный биллинг ChatGPT и API](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform) и [документы Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source).

Текущая сборка **не подключается к локальному приложению Codex или процессу `codex app-server`** и не использует их вход/подписку для подбора сцен. Codex CLI/приложение — отдельный agent runtime, а не URL OpenAI-compatible API; добавить его адрес в форму API-профиля недостаточно. Официальная интеграция Codex внутрь другого приложения — отдельная функция, которая не входит в этот релиз. Не передавайте приложению токены или внутренние файлы Codex вручную.

## Как быстро проверить приложение

1. Без AI откройте **По объектам**, задайте несколько доступных названий предметов и соберите сцену. Проверьте выбор палитры и формата.
2. На странице `/ai` активируйте профиль, загрузите модели и выберите одну из них.
3. Выполните два смыслово разных запроса, например про учебный проект и про тихий отдых. Убедитесь, что интерфейс сообщает об успешном ответе AI. Если написано, что применён offline fallback, композицию построили локальные правила.
4. Попробуйте перетащить предмет, поменять порядок слоёв и экспортировать SVG. Откройте экспортированный SVG в браузере.
5. Сверьте результат с демонстрационными сценами в `Source/SVG_Auto/examples/`.

## Типовые ошибки

- **401/403** — проверьте ключ, тип протокола и доступ аккаунта к API/модели.
- **429** — провайдер ограничил частоту или квоту. Подождите, выберите другую доступную модель или используйте локальный fallback.
- **Ошибка загрузки моделей / пустой список** — проверьте базовый URL, поддержку endpoint списка моделей и права API-ключа. Не каждый совместимый endpoint публикует полный каталог.
- **Соединение прошло, но план сцены заменён offline-правилами** — модель или сервис ответили в формате, не прошедшем JSON/предметную проверку. Приложение не применяет непроверенный план.
- **Профиль не работает после переноса** — секреты не переносятся вместе с ZIP. Добавьте профиль на новом компьютере.

## Сборка исходников без Visual Studio

Для редактирования и сборки понадобится **.NET 10 SDK**, но не Visual Studio. Если SDK уже установлен, распакуйте полный ZIP и выполните в PowerShell:

```powershell
cd .\Source\SVG_Auto
dotnet restore .\OmegaIllustrator.slnx
dotnet test .\OmegaIllustrator.slnx -c Release
dotnet run --project .\src\OmegaIllustrator.Web\OmegaIllustrator.Web.csproj --no-launch-profile -- --urls http://127.0.0.1:5190
```

Отдельные тесты AI-библиотеки запускаются из соседней папки:

```powershell
cd ..\DLL_OMEGA_LAB_CONNECT_AI
dotnet test .\Omega.AI.Gateway.sln -c Release
```

Сборка Windows x64 для распространения:

```powershell
cd ..\SVG_Auto
dotnet publish .\src\OmegaIllustrator.Web\OmegaIllustrator.Web.csproj -c Release -r win-x64 --self-contained true -o .\publish\win-x64
```

Готовая поставка уже включает самодостаточную публикацию в `Application/`; пересобирать её обычному пользователю не требуется.

## Git и что передавать

В Git нужны исходники приложения, исходники и тесты AI-библиотеки, runtime SVG под `wwwroot/Assets`, тесты, документация, JSON-примеры и исходник извлекателя. В Git не добавляются: API-ключи и локальный каталог данных, сборочные папки, `dist/`, ZIP, видео и исходный `.fig`. Файл `.fig` не нужен для запуска; он остаётся в передаваемом архиве/на Google Drive для повторного извлечения ресурсов. Перед внешней публикацией уточните у владельца задания, разрешена ли передача исходных SVG и исходника Figma в выбранный репозиторий; до этого используйте приватный доступ.

Приложение и отдельная библиотека ведутся в двух локальных Git-репозиториях. Для сборки из клонов они должны лежать соседними папками с именами `SVG_Auto` и `DLL_OMEGA_LAB_CONNECT_AI`; ссылка `ProjectReference` в решении приложения рассчитана на это расположение. У обоих локальных репозиториев пока не настроен удалённый адрес. До push нужно задать владельцу корректные URL приватных репозиториев для приложения и AI-библиотеки.

Архив и видео удобнее передать отдельно через Google Drive. В Git достаточно положить исходный проект и документацию, а в репозитории указать SHA-256 архива и ссылку на разрешённую папку передачи.
